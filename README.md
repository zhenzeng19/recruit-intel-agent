## 三、首次使用

```bash
cd E:/zzl_workbuddy_datas/招聘agent

# 1. 安装依赖（根目录执行，workspaces 会一次性装好所有子包）
npm install --ignore-scripts

# 2. 配置环境变量
cp .env.example .env      # 然后按需编辑

# 3. 一键构建，产物输出到 ../招聘agent-build
npm run build

# 4. 跑起来（后端会一并托管前端看板）
npm run start             # 打开 http://localhost:8787/

# 5. 清空产物
npm run clean
```

> **数据从哪来？** 首次启动时若数据目录为空，会自动灌入 **5 个岗位 + 22 份示例候选人简历**
> （半导体量检测 / 面板检测 / 工业视觉方向），终端会打印 `已自动灌入示例数据：22 份候选人简历`。
> 想换成干净的一批，点看板左侧「重置示例数据」。

> **为什么加 `--ignore-scripts`？**
> esbuild 的安装后脚本会在本机环境下触发 Windows `EBUSY`（进程占用）导致整个安装回滚。
> 加上该参数跳过安装脚本即可，esbuild 的平台二进制由 `@esbuild/win32-x64` 提供，功能不受影响。
> 如果后续报「找不到 @esbuild/win32-x64」，执行：
> ```bash
> npm install --include=optional --ignore-scripts
> ```

## 四、看台（七个模块）

打开 `http://localhost:8787/` 就是完整看台：**左侧常驻导航，七个入口点击即切换**。
切换写进 URL hash（`#/library`、`#/pipeline`…），所以刷新、前进后退、把链接发给同事，都能落到同一页。

| 入口 | 地址 | 它回答什么问题 |
|---|---|---|
| **候选人库** | `#/library` | 我找过谁？什么岗位、什么进度、匹配多少分 |
| **岗位漏斗** | `#/pipeline` | 每个岗位卡在哪一环、该往哪补人 |
| **岗位管理** | `#/positions` | **自己加岗位**、改 JD、停用/删除，以及「重跑匹配」给待匹配的人补挂岗位 |
| **每日简报** | `#/daily` | 今天该推谁、该跟进谁 |
| **人才 Map** | `#/talentmap` | 候选池的城市 / 公司 / 院校 / 技能结构 |
| **智能问答** | `#/qa` | 用人话查库，如「深圳 85 分以上有哪些人」 |
| **待办中心** | `#/todos` | 哪些流程卡住了，按紧急度排好序 |

七个页面**共用同一批数据** —— 改一个候选人的进度，漏斗 / 简报 / 待办会跟着变。
页面之间也能互相跳：简报里点某个候选人，会直接切到候选人库并打开他的详情；漏斗里点岗位会跳到库并预设筛选。

### 4.1 候选人库

| 能力 | 说明 |
|---|---|
| **分门别类** | 一个候选人关联到哪个岗位、什么进度、匹配多少分，一屏看清 |
| **关键词检索** | 姓名 / 公司 / 学校 / 专业 / 技能 / 简历正文全文匹配（多词 AND 收窄） |
| **多维筛选** | 按岗位、招聘进度、简历来源、最低匹配度过滤 |
| **匹配可核对** | 每份简历都给出**命中点**和**缺失点**，不是黑盒打分 |
| **进度可推进** | 详情抽屉里直接改「待沟通 → 已沟通 → 筛选 → 面试 → Offer → 入职」 |
| **来源可溯源** | 每条来源带平台、平台内 ID、采集时间、原页链接，以及**采集方式（自动 / 手动保存）** |
| **无感采集入库** | 扩展上报的简历按 `(平台, 平台内ID)` 自动去重，同一人不会重复建档 |
| **采集开关** | 扩展三档模式：**保存前询问（默认）/ 自动 / 关闭**；改完立即生效，不用刷新页面 |
| **逐份决策** | 页面上浮动卡片，可对**这一份**说「保存到看板 / 这次不存 / 本页都不再问」 |
| **手动补采** | 自动没抓到但你知道是简历时，一键放宽门槛保存；正文不完整会**如实提示**，不偷偷存脏数据 |
| **列表页让路** | 人才推荐 / 搜索这类「一屏多人」的页面不自动采集，避免存进包含多个人的脏数据 |
| **保存时选岗位** | 卡片 / 面板上直接选「这份简历挂到哪个岗位」，**记住上次的选择**；不选就按规则自动挂 |
| **学历性质可筛** | 抓 **统招 / 非统招**（招聘软件普遍识别不了），并**存下原文依据**便于核对 |
| **字段抓得全** | 姓名 / 性别 / 年龄 / 城市 / 学历 / 学校 / 专业 / 985·211 / 工作年限 / 薪酬（含 ×13 薪）/ 当前公司与职位 / 平台推荐职位 / 技能标签 |
| **导出 PDF 给业务部门** | 参照猎聘排版生成正式简历页 → **打印即存为 PDF**；带姓名 + 应聘岗位 + 匹配度；可按岗位**批量导出一个多页 PDF** |
| **导出 Excel（筛选结果）** | 当前筛选的**全部**候选人一键导成真正的 `.xlsx`（不是 CSV）：冻结表头 + 自动筛选 + 数字列可排序；文件名 `<岗位>_<日期>_推荐名单.xlsx`；精简 14 列 / 完整 25 列 |
| **删除简历** | 单份或批量删除，删除前**自动归档**到 `_deleted/`（误删能捞回来）；可勾「**不再采集此人**」—— 以后即使又打开他的简历也不会再存进来 |

### 4.2 导出简历 PDF（交给业务部门）

采集到的是**页面文本**，直接发给业务部门不合适。所以有导出：

| 入口 | 做什么 |
|---|---|
| 候选人抽屉右上「导出 PDF」 | 单人导出，可选：匹配度与命中点 / 来源与采集时间 / 附未结构化原文 |
| 岗位卡片的「导出候选人 PDF」（漏斗页与岗位管理页都有） | **把该岗位下的全部候选人合成一个多页 PDF** —— 「分岗位给业务部门」的正解 |
| 候选人库勾选多人 → 「导出选中 PDF」 | 自选组合批量导出 |

点完之后浏览器会打开一个排版好的简历页并**自动唤起打印对话框**，在那里选「另存为 PDF」即可。

**关于 PDF 的实现选择**：没有用服务端 PDF 引擎，而是**浏览器打印**。原因：
① 本机已确认无头 Chrome 拿不到输出（踩过两次）；② PDF 库必须嵌入中文字体（10~20MB）并手写排版。
浏览器打印用系统字体栈，**中文不会乱码、零新增依赖、便携包里也能用**。代价是多一次「另存为 PDF」的点击。

导出的页面长这样：

```
┌──────────────────────────────────────────────────┐
│ 李先生                              应聘岗位      │
│ 38 岁 · 盐城 · 本科(非统招) · 15 年经验  项目经理  │
│ 某某师范大学 · 计算机科学与技术 · 211   匹配度 84 │
├──────────────────────────────────────────────────┤
│ 求职意向   项目经理/主管 · 26-27k×12 · 盐城        │
│ 工作经历   某某动力工业有限公司 / MES资深工程师 │
│ 教育经历   某某师范大学 · 本科 · 计算机科学与技术   │
│ 技能标签   Python  MES  Linux  …                  │
├──────────────────────────────────────────────────┤
│ 来源：<这份简历自己的链接> ｜ 采集时间 … ｜ 手动保存 │
│ 本简历由「招聘捕手」从猎聘在线简历文本自动生成，      │
│ 非候选人原附件简历，仅供内部招聘评估使用。          │
└──────────────────────────────────────────────────┘
```

> ⚠️ **两个边界**：① 候选人上传的**附件简历**需要向 TA 索要才能看，我们抓不到 —— 导出的是**在线简历文本**排的 PDF，所以页脚有免责说明；
> ② 来源链接带猎聘的签名参数且需要登录你的招聘账号，**业务部门点不开** —— 链接是给你自己溯源的，PDF 才是给业务部门的。

### 4.3 岗位漏斗

每个岗位一条按比例伸缩的彩色漏斗条（颜色对应进度状态），下面列出各阶段人数。
同时给岗位级的候选人总数、平均匹配度、强推（≥85 分）人数。点「查看该岗位全部候选人」跳到库里并预设好筛选。

### 4.4 每日简报

一句话摘要 + 三栏清单：**今日新增 / 今日优先联系 / 该跟进了**，最后附各岗位进展表。
「该跟进了」的判定规则偏保守（只在确实卡住或高分没人管时提醒），避免变成噪音。

### 4.5 人才 Map

城市 / 学历 / 工作年限分布、**技能热度云**（字号随出现次数变化）、公司来源 Top 10、院校 Top 10，
以及**岗位 × 技能矩阵** —— 用来对 JD 和调筛选词。

### 4.6 智能问答

当前是**规则引擎**：先把问句解析成检索条件（岗位 / 城市 / 学历 / 进度 / 来源 / 分数），再回库检索，最后拼出人话结论。
界面上会显示「解析为」了哪些条件，结果可核对。结果一定来自真实数据，不会编。
接上大模型后只需把解析与成文交给模型，**检索这一层不变**。

### 4.7 待办中心

按 `今天必须处理 / 这两天处理 / 有空再看` 三档分组。规则示例：

| 触发条件 | 优先级 |
|---|---|
| 已发 Offer 超过 3 天没更新 | 高 |
| 面试中超过 5 天没更新 | 高 |
| ≥85 分但超过 2 天没联系 | 高 |
| 筛选 / 已沟通超过 7 天没推进 | 中 |
| 待沟通超过 5 天 | 中 |
| 70–84 分排队中 | 低 |

| GET | `/api/daily` | 每日简报（今日新增 / 推荐 / 待跟进 / 岗位摘要） |

| POST | `/api/capture` | 采集上报入口（浏览器扩展调用，含去重） |

> 漏斗 / 简报 / 人才 Map / 待办都是**视图**，不是独立的表 —— 从 `candidates` / `matches` / `sources` 现算。
> 放在后端算的原因：只有后端能看到全量数据，前端分页拿不全。

**调试 / 安装浏览器扩展**：

- 在 Trae 里按 `F5` 选「调试扩展」会自动构建并拉起带扩展的浏览器窗口
- 手动装到自己常用的 Edge / Chrome：见 **[docs/Edge安装扩展指南.md](./docs/Edge安装扩展指南.md)**
  ```bash
  npm run build        # 构建
  npm run verify:ext   # 校验产物完整性（含域名覆盖：拿真实页面 URL 跑 match pattern）
  npm run test:extract # 提取逻辑单测（40 项）
  npm run test:ext     # background 集成测试（39 项，自带隔离后端，跑完自动清理）
  ```
  然后 `edge://extensions` → 开发人员模式 → 加载解压缩的扩展 →
  选 `E:/zzl_workbuddy_datas/招聘agent-build/extension`

> **改了扩展代码后**：`npm run build` → `edge://extensions` 点扩展卡片的**刷新** → **F5 刷新招聘页面**。
> 最后一步最容易忘：content script 只在页面加载时注入，不刷新页面跑的还是旧代码。

> 扩展装了以后**点图标会弹出状态面板**：后端连通 / 本地队列 / 已入库数量 / 当前标签页状态，
> 还有一个 **「诊断当前页」** 按钮，直接告诉你页面上有没有识别到简历内容。

> **采不到数据？** 见 **[docs/采集排查指南.md](./docs/采集排查指南.md)**。
> 猎聘要特别注意：HR 用的企业端在 `lpt.liepin.com`，与主站 `www.liepin.com` 是两个域名，
> 扩展的匹配规则必须覆盖到子域（0.1.0 就没覆盖，导致企业端页面上完全静默失效）。

## 六、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端看板 | React 18 + Vite 5 + TypeScript | 快、轻、生态成熟 |
| 后端 | Node + Fastify 5 + TypeScript | 轻量高性能，esbuild 打包 |
| 浏览器扩展 | MV3 + TypeScript（Edge / Chrome 通用） | 被动采集，esbuild 打包 IIFE，含状态 popup |
| 数据存储 | **本地 JSON 文件库**（`apps/server/src/db/`） | 零依赖、可肉眼核对；仓储层已解耦，换云库只替换一个实现 |
| 共享代码 | `@ria/shared` workspace 包 | 三端共用类型与常量 |
| 云端 | cloud-service（数据库 / 对象存储 / 认证 / 大模型） | 待接入，见 [数据存储方案](./docs/数据存储方案.md) |
