# 采集排查指南 —— 「扩展装了却没采到」

适用场景：扩展已经装进 Edge / Chrome，也在招聘网站上点开了简历，但看板上没有任何新数据。

---

## 一、先确认一件事：你装的是哪个版本

打开 `edge://extensions`，找到「招聘捕手」，看卡片上的**版本号**。

| 你要看到的 | 说明 |
|---|---|
| **0.2.0** | 本次修复后的版本。猎聘企业端（`lpt.liepin.com`）已被覆盖 |
| 0.1.0 | 旧版本。它在猎聘上**根本不会工作**，见下面的「本次修了什么」 |

### ⚠️ 如果你当初是用「打包扩展」装的 crx

打包出来的 `.crx` 是**一次性快照**——源码改了、重新 `npm run build` 了，crx 依然是旧代码，点刷新也没用。

**推荐改用「加载解压缩的扩展」**（改完代码只需点刷新，不用重装）：

1. `edge://extensions` → 先**移除**旧的「招聘捕手」
2. 确认左下角「开发人员模式」已打开
3. 点「加载解压缩的扩展」→ 选目录：
   ```
   <项目所在目录>/招聘agent-build\extension
   ```
4. 确认卡片版本号是 **0.2.0**

> 顺便提醒：`招聘agent-build/extension.pem` 是打包私钥，**不要提交到 git、不要外传**。
> 它现在在仓库同级目录里，git 不会跟踪，是安全的。

---

## 二、五步定位法

从下往上排查，哪一步断了就是哪里的问题。

### 第 0 步（0.4.0 新增）：**采集开关是不是关着 / 是不是在等你点**

0.4.0 起扩展有三档模式，**默认是「保存前询问」** —— 也就是说
**识别到简历后它不会自己入库，而是在页面右下角弹一张卡片等你点「保存到看板」**。
所以「采不到」的第一嫌疑不是坏了，而是：

| 现象 | 说明 |
|---|---|
| 页面右下角有个小圆点，点开写着「识别到 xxx · 尚未入库」 | 正常，正等你决定。点「保存到看板」即可 |
| popup 面板的模式显示「关闭」 | 自动采集被关了。手动保存仍然可用（面板里的「保存到看板」） |
| popup 里那张卡片被拖到过别的位置 | 位置会记住。找不到就点 popup 的「诊断当前页」，或直接在面板里保存 |
| 这一页曾点过「本页都不再问」 | popup 会显示「本页已被设为都不再问」+「恢复本页采集」按钮（7 天后自动失效） |

**先看 popup 顶部的模式**，再往下走五步。想回到全自动，把模式切成「自动」即可 —— **改完立即生效，不用刷新页面**。

### 第 1 步：重载扩展后，**页面刷新了吗**

这是最常被忽略的一步。

> **重载/更新扩展，不会自动注入到已经打开的页面。** 必须按 `F5` 刷新招聘网站页面，新的 content script 才会进去。

### 第 2 步：扩展注入了吗

在猎聘（或 BOSS）页面上按 `F12` 打开控制台，看有没有这一行：

```
[招聘捕手] ● 已注入：猎聘（top）· 排查用：Console 输入 __ria.scan()
```

| 情况 | 含义 |
|---|---|
| 看到这行 | ✅ 已注入，进第 3 步 |
| 没有这行，且 `__ria` 是 `undefined` | ❌ **扩展没注入到本页** —— 见下面「如何判断是域名问题」 |
| 有这行但显示 `iframe(...)` | ✅ 说明简历内容在内嵌框架里，扩展已在框架内就位 |

**如何判断是域名问题**：在控制台执行

```js
__ria === undefined        // true 表示脚本压根没进来
location.hostname          // 看看当前到底是什么域名
```

如果 `location.hostname` 是 `lpt.liepin.com`、而扩展版本还是 0.1.0 —— 那就是本次这个 bug。

### 第 3 步：识别到简历内容了吗

**方法 A（推荐）**：点扩展图标 → 新增的「诊断当前页」按钮，面板里会直接给出结论。

**方法 B**：控制台执行

```js
__ria.scan()
```

输出长这样：

```
[招聘捕手] 诊断 · 猎聘 · top
  → 已识别简历内容区（智能识别，1842 字），链路正常
┌─────────┬────────────────────────────────┬───────┬──────┬───────┐
│ (index) │ el                             │ chars │ hits │ score │
├─────────┼────────────────────────────────┼───────┼──────┼───────┤
│ 0       │ div.candidate-profile-body     │ 1842  │ 8    │ 80    │
└─────────┴────────────────────────────────┴───────┴──────┴───────┘
```

### 第 4 步：上报了吗

如果第 3 步正常，控制台应该紧跟着出现：

```
[招聘捕手] ✓ 捕获到候选人：data-resumeid:R-998877（智能识别，1842 字）
```

没出现的话，执行 `__ria.capture()` 手动触发一次，看报什么错。

### 第 5 步：入库了吗

点扩展图标：

- **「本地待上传队列」= 0 且「已入库」在涨** → ✅ 全链路通了
- **队列 > 0** → 后端没收到，点「立即同步」看错误提示
- 「已入库」不动、队列也空 → 大概率是**判重**了（这个人之前采过），看「判重跳过」数字

## 三、诊断结论对照表

### ✅ `已识别简历内容区（…），链路正常`

没问题。如果看板还是没数据，往下查同步：后端起没起（`npm run start`）、扩展里的后端地址对不对（`http://localhost:8787`）。

### ⚠️ `有 N 个疑似容器但都未达阈值（最高 X 分 / 需 18）`

简历面板**还没渲染完**，或者还没点开。排查：

1. 确认你真的**点开了某位候选人的在线简历**（预览面板处于展开状态），只是停留在会话列表页是不够的
2. 等 2~3 秒再执行一次 `__ria.scan()`
3. 还是不行的话，把 `__ria.scan()` 的 `topCandidates` 表格截图发我 —— 说明站点结构变了，需要补一条选择器

### ❌ `页面有 N 个 canvas、M 张图片，但摘不出简历文本`

**这份简历是图片 / canvas 渲染的**，页面 DOM 里根本没有文字，抓不到。

这不是 bug，是这类平台的防抓取手段。解决办法只有一条：**整屏截图 → 多模态模型 OCR 解析**。这块属于 P2 计划，还没做。

怎么确认：在简历页面上按住 `Ctrl+A` 全选，如果能选中文字 → 是 DOM 渲染（应该能采到）；如果选不中、像选中了一张图 → 确认是图片渲染。

### ❌ `本框架内没有简历文本，页面有 N 个 iframe`

简历在内嵌框架里，但框架没被注入。检查扩展版本是否 ≥ 0.2.0（该版本开了 `all_frames`）。

### ❌ `未识别到简历内容区`

你还没点开任何一份简历，或者简历面板被关掉了。

## 四、采到了，但看板里看不到？（第二轮修复）

现象：扩展 popup 上「已入库」在涨，`招聘agent-data/candidates.json` 里也能搜到人，
但打开看板刷了半天还是那批老数据。

这不是一个 bug，是**两个原因叠在一起**：

| # | 原因 | 表现 | 修法 |
|---|---|---|---|
| 1 | 看板**完全没有自动刷新**：只在页面挂载时拉一次数据，之后只在你改筛选条件时才重新请求 | 扩展在别的标签页把数据推进后端，看板毫不知情，必须手动 F5 | 看板轮询 `/api/revision`（一个只读整数），版本一变就自动重拉；切回标签页/窗口获得焦点时也会补查一次；左下角另有「立即刷新」按钮 |
| 2 | 新采集的候选人**没有岗位匹配** → `score` 为空 → 列表默认按匹配度倒序，`?? -1` 直接压到最底 | 25 人里你采的那 3 条排在最后三名，第一屏全是示例数据（93/92/91…），看着就像「没刷新」 | 采集入库时立刻做一次**规则初筛匹配**（`rule-v1`），让新简历有分、能正常参与排序；同时补两个兜底入口 |

### 兜底入口在哪

- 顶部统计卡 **「今日采集」** → 点一下切到「最新采集优先」排序
- 统计条下方的蓝色提示条 **「有 N 份简历还没有归到任何岗位」→ 只看待匹配**
- 左侧筛选面板里：排序选 **「最新采集优先 ★」**，或勾上 **「只看待匹配」**
- 候选人卡片上直接标了 **「采集 X 分钟前」**，一眼能看出哪几条是刚进来的

### 规则初筛是什么意思

采集进来的只有一段简历原文，没有「面试官判断」。为了不让它沉底，落库时先用一套
行业术语表给简历打个分、挂到最对口的在招岗位上：

- 打分口径：基础分 30 + 岗位要求术语覆盖率 × 50 + 标题核心词命中 12 + 学历达标 6，上限 94
- 上限刻意压在 94：**规则分永远进不了「强推」区间**，不占高分名额、不挤掉后续的人工/大模型判断
- 每条匹配都标了 `modelVersion: "rule-v1"`，命中理由里也写明「规则初筛，等大模型结构化后复核」
- 一个人只挂**一个**主岗位，不往岗位漏斗里灌一堆低分岗位

接上大模型（P1）之后，模型会覆盖同一批 match，前端不用改。

### 我已经采进来的脏数据怎么办

改好提取逻辑，**已经入库**的简历不会自动变好（姓名还可能是「查看大图」、同一个人还占着几条档案）。
`scripts/repair-data.mjs` 会用当前的真实代码把历史数据重跑一遍：

```bash
npm run repair:data                      # 预览：只打印将要做的改动，不动数据
npm run repair:data -- --write           # 执行（会先备份到 <数据目录>/_backup/<时间戳>/）
```

它做三件事，顺序不能反：

1. **重跑字段粗提取** —— 姓名 / 城市 / 学历 / 手机号 / 邮箱
2. **合并重复档案** —— 按「姓名 + 公司/学校」归组，保留正文最长的那条，来源记录全部迁移过去
   （必须在第 1 步之后：合并是按姓名分组的，而历史数据的姓名还是被按钮顶掉的「查看大图」「意向沟通」，
   先合并的话同一个人因为名字不同会被分成好几组，一条都合不掉）
3. **给仍无岗位匹配的候选人补规则匹配**

## 五、上一轮修了什么（猎聘采不到）

你给的页面是 `https://lpt.liepin.com/chat/im?jobId=85838997&jobKind=2&tab=message#preview`，
这条 URL 一暴露，就同时踩中了 6 个问题：

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | manifest 只匹配 `www.liepin.com`，而 HR 端在 **`lpt.liepin.com`** | **脚本压根没注入**，连报错都没有 | 覆盖 `liepin.com` 及其所有子域；BOSS 同理 |
| 2 | 简历页判定只认 `/resume` | `/chat/im` 被判定为「不是简历页」 | 改为不靠 URL 猜，直接找内容 |
| 3 | **同一 URL 就跳过采集** | IM 页切换候选人 URL 不变 → **永久漏采** | 改为「内容签名」判重 |
| 4 | 候选人 ID 取 URL 末段，`/chat/im` 取到 **`im`** | 同一职位下所有人撞成同一个 ID，被全部判重丢弃 | 禁止用路由词；按 resumeId → DOM 属性 → 内容指纹分级兜底 |
| 5 | 截取整个 `document.body` | 会把导航、会话列表、聊天记录一起抓进去 | 只取「最小充分容器」里的简历正文 |
| 6 | 没监听 `hashchange`、`all_frames` 未开 | 点开简历（`#preview`）不触发；iframe 内采不到 | 补 hashchange 监听；开启 `all_frames` |

其中 **第 1 条是决定性的** —— 前面 5 条再严重也没机会发作，因为脚本从来没在页面上跑起来。

## 六、常见问题

### Q：为什么不用硬编码的选择器，而是「智能识别」？

招聘站点改版很频繁，而且同一站点不同入口（列表页 / IM 页 / 详情页）的 DOM 结构完全不同。硬编码一条选择器就是赌它不改版。

现在的做法是两级：

1. **站点提示选择器**优先（我按已知结构维护了一批，命中即采信）
2. 没命中就走**启发式**：在页面里找「同时满足 ① 文本够长 ② 命中足够多简历章节词（工作经历/教育经历…）③ 不夹带招聘端外壳词（消息/通讯录/职位管理…）」的**最小**容器

第 2 条的好处是：站点改版、换入口，只要还是「一块装着简历文字的 DOM」，就还能工作。

### Q：切换候选人不刷新页面，会重复采集吗？

不会。判重基于「平台 + 候选人 ID + 正文长度」的内容签名，同一个人重复出现会被跳过；换人则一定被识别为新简历。

### Q：同一份简历在 iframe 和主框架里都能找到，会存两条吗？

理论上有可能，实际很少见（简历通常只在一处）。真遇到了告诉我，可以在服务端按「姓名 + 手机/邮箱」做跨框架合并。

### Q：怎么改采集范围 / 调整识别规则？

- **加站点**：`apps/extension/src/extract.ts` 里的 `SITES`，加一条 `SiteProfile`，同时更新 `manifest.json` 的 `matches` 和 `host_permissions`
- **调阈值**：同文件的 `MIN_RESUME_CHARS` / `PASS_SCORE` / `NOISE_WORDS`
- 改完执行 `npm run build`，然后到 `edge://extensions` 点扩展卡片上的**刷新**，再 `F5` 刷新页面

新增站点后，`npm run verify:ext` 会告诉你域名覆盖对不对（它拿真实 URL 跑 match pattern）。

### Q：扩展会不会偷偷上传我的聊天记录？

不会。只有「被判定为简历内容区」的那块文本会被提取，且只发给 `localhost:8787`（或你在 `.env` 里配的地址）。发之前你可以在控制台用 `__ria.extract()` 预览将要上报的完整内容。

## 七、常用命令速查

```bash
cd <项目所在目录>/招聘agent

npm run build                # 重新编译（改完扩展代码必跑）
npm run typecheck            # 三端类型检查
npm run verify:ext           # 产物自检：域名覆盖、元素 ID、权限
npm run test:extract         # 提取逻辑单测（59 项：姓名识别 / 去重稳定性 / 指纹）
npm run test:ext             # background 集成测试（39 项）
npm run test:store           # 数据层集成测试（33 项：自动匹配 / revision / 去重 / 字段提取）
npm test                     # 上面几项一把跑完
npm run repair:data          # 修复历史脏数据（预览；加 -- --write 才落盘）
npm run start                # 起后端 + 看板 http://localhost:8787
```

改完扩展代码的标准动作：

```
npm run build  →  edge://extensions 点「刷新」  →  F5 刷新招聘页面
```

改完前端（`apps/web`）的标准动作：

```
npm run build  →  F5 刷新看板
```

⭐ **看板现在会自动刷新**：页面每 5 秒问一次后端的 `/api/revision`，数据一变就自己重拉，
不用手动 F5。切回标签页 / 窗口获得焦点时也会立刻补查一次。左下角另有「立即刷新」按钮。

1. `edge://extensions` 里扩展卡片的**版本号**
2. 招聘页面上 `__ria.scan()` 的**完整输出**（含 `topCandidates` 表格）
3. 扩展「诊断当前页」按钮的结果截图
