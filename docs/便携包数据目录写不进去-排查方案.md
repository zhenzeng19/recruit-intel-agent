# 便携包「数据目录写不进去」—— 排查与解决 方案

> 2026-10-05 · 对应现象：`EPERM: operation not permitted, open 'D:\招聘agent-portable\data\.write-probe-xxxxx'`
> 相关版本：便携包 0.5.5（已带自动退路）

---

## 〇、先说三句结论

1. **现在就能用** —— 0.5.5 已经自动把数据放到 `%LOCALAPPDATA%\招聘agent-data`，看板功能一切正常。
   所以这**不是**「必须马上修」的问题，而是「**要不要把数据放回包文件夹**」的选择。
2. **根因还没确定** —— 我知道那个目录写不进去，但**不知道是哪一种原因**。
   §一 给一条命令，跑完就知道。不要凭猜去改系统设置。
3. **最省事的解法不是修权限，而是改一行配置**（§二 路线 A）。

---

## 一、先确定根因（跑一条命令，把输出发我）

在**包里**开命令行（在地址栏输入 `cmd` 回车），或开 PowerShell，粘贴执行：

```powershell
$pkg = "D:\招聘agent-portable"
"1) 包根目录能否写："
try { Set-Content "$pkg\_t.txt" ok -ErrorAction Stop; "   能写 OK"; Remove-Item "$pkg\_t.txt" -Force } catch { "   不能写 -> $($_.Exception.Message)" }
"2) data 目录能否写："
try { Set-Content "$pkg\data\_t.txt" ok -ErrorAction Stop; "   能写 OK"; Remove-Item "$pkg\data\_t.txt" -Force } catch { "   不能写 -> $($_.Exception.Message)" }
"3) data 目录属性："
(Get-Item "$pkg\data").Attributes
"4) data 目录权限（重点看有没有 Deny）："
icacls "$pkg\data"
"5) D 盘类型与剩余空间："
Get-PSDrive D | Select-Object Root, Used, Free
Get-Volume -DriveLetter D -ErrorAction SilentlyContinue | Select-Object DriveLetter, FileSystemType, DriveType, OperationalStatus
"6) 有没有杀毒软件常驻："
Get-Process -ErrorAction SilentlyContinue | Where-Object { $_.ProcessName -match '360|huorong|hrsword|QQPCTray|kxescore|MsMpEng|zhudongfangyu|baidu|Kingsoft' } | Select-Object ProcessName, Id
```

### 输出怎么读

| 观察 | 结论 |
|---|---|
| 1 能写、2 不能写 | 只有 `data` 这一个子目录被限制 → **ACL / 杀软针对该目录** |
| 1 和 2 都不能写 | 整个 `D:\招聘agent-portable` 都不可写 → **D 盘层面**（只读介质 / 单位策略 / 权限） |
| 4 里出现 `(DENY)` | **ACL 显式拒绝** → 路线 C-2 |
| 5 的 `DriveType` = `Removable` 或 `CD-ROM` | **可移动/只读介质** → 路线 C-3（换到硬盘） |
| 5 的 `FileSystemType` 不是 NTFS | 非 NTFS（FAT32/exFAT）对 `改名覆盖` 支持差 → 我们已经加了直写退路，但仍建议换到 NTFS |
| 6 列出了杀软 | **大概率是杀软拦截**（未签名的 node.exe 新建文件被拦）→ 路线 C-1 |
| 全都正常但就是报 EPERM | 同步盘占位文件 / 单位安全软件（看不到进程那种）→ 路线 A 或 B 最省事 |

## 二、解法（三条路，按「省事程度」排序）

### 路线 A ★最省事：改一行配置，把数据放到你自己指定的目录

`.env` **支持绝对路径**（已确认代码里是 `path.isAbsolute(value) ? value : ...`），所以：

1. 用记事本打开包里的 **`.env`**
2. 把这一行
   ```
   DATA_DIR=data
   ```
   改成（路径自己定，**别放 C 盘受保护目录**）
   ```
   DATA_DIR=C:\招聘数据
   ```
3. 保存 → 重新双击 `启动看板.vbs`

**优点**：完全绕开 D 盘的权限问题；路径你自己掌控；一劳永逸。
**缺点**：数据不在包文件夹里（和现在的自动退路本质一样，但这是**你主动选的、明确的**）。

> 为什么推荐它：你要的是「能干活」，而不是「必须把数据放在某个特定文件夹」。
> 跟系统的权限策略斗通常不划算。

### 路线 B ★推荐给「想整包拷走」：把整个文件夹移到用户目录

1. 停止看板（双击 `停止看板.bat`）
2. 把整个 `招聘agent-portable` 文件夹**移到**
   ```
   C:\Users\<你的用户名>\
   ```
   即最终路径形如 `C:\Users\你的名字\招聘agent-portable`
3. 双击 `启动看板.vbs`

**优点**：数据回到包内目录，以后**整个文件夹拷走就带上数据**；用户目录一定有写权限。
**缺点**：要移动文件夹（约 1 分钟）。

验证是否成功（在包文件夹里开命令行）：
```cmd
echo test > data\writetest.txt
```
不报「拒绝访问」就成了（然后把 `data\writetest.txt` 删掉）。

> ⚠️ 别放在 `C:\Program Files`、`C:\Windows` 这类受保护目录 —— 那里需要管理员权限。

### 路线 C：留在 D 盘，对症解决根因

按 §一 的结论选一条：

**C-1 杀软拦截**（最常见之一）
- 360 / 火绒 / 电脑管家 → 把 `D:\招聘agent-portable` 加入**信任区/白名单**
- 或临时彻底退出杀软，验证一次是否恢复（验证完记得开回来）
- 为什么会被拦：包里的 `node.exe` 是**未签名**的官方运行时，很多国产杀软对「新解压出来的未签名 exe 创建文件」有主动防御

**C-2 ACL 显式拒绝**（`icacls` 输出里有 `(DENY)`）
- 看是谁的 Deny，然后移除：
  ```cmd
  icacls "D:\招聘agent-portable\data" /remove:d "用户的域名\用户名"
  ```
- 或者重新继承父目录权限：
  ```cmd
  icacls "D:\招聘agent-portable\data" /reset /T
  ```
- ⚠️ 改权限前先记一下当前输出（`icacls` 的结果），万一改坏了能对着恢复

**C-3 只读介质 / 单位策略**
- 如果 `DriveType` 是 `Removable` / `CD-ROM`，或 D 盘是单位统一管理的策略盘 → **换到本机硬盘的用户目录**（就是路线 B）
- 这种情况**不建议**硬改：多半是物理写保护或域策略，改了也会被重置

**C-4 同步盘占位文件**
- 如果 D 盘在 OneDrive / 坚果云等同步目录里 → 把包**移出同步目录**，或暂停该目录同步

## 三、已经产生数据了怎么办（搬迁步骤）

如果你已经在用（数据现在在 `C:\Users\<你>\AppData\Local\招聘agent-data`），
而你想改回包内目录，**数据不会自己搬过去**，要手工搬：

1. **先停看板**（双击 `停止看板.bat`）
2. 按路线 A / B / C 之一，把目标目录弄成**可写**
3. 打开 `C:\Users\<你>\AppData\Local\招聘agent-data`，把里面**全部 `.json`** 复制到
   - 路线 A → 你新设的目录（如 `C:\招聘数据`）
   - 路线 B/C → 包内的 `data` 目录
4. 重新启动看板 → 看首页的**候选人数量**是否和之前一致（对不上就说明没搬全）

⚠️ **别在两个位置都留一份数据然后来回切** —— 那会看起来像「数据丢了/回退了」。
搬完把旧位置清空（或改名加个 `.bak` 后缀留着）。

## 四、我建议你怎么做（如果你问我）

**就用路线 A，然后忘了这件事。**

```
改 .env:  DATA_DIR=C:\招聘数据
```

理由：
- 你的目标是采简历、看板汇总、导 Excel/PDF —— **数据放哪个盘不影响这些**
- 路线 A 不用跟杀软/ACL/介质打交道，**改一行、立即生效、不会反复**
- 唯一代价是「整包拷走不带数据」——而这件事可以单独做：要搬运时把 `C:\招聘数据` 一起拷

**除非**你明确需要「一个文件夹拷走就啥都有」——那就走路线 B（移到用户目录）。

## 五、程序侧我还能做的（可选，你说了我再做）

| # | 改进 | 价值 | 风险 |
|---|---|---|---|
| 1 | **加一个「自检.bat」**：双击输出一份体检报告（能否写数据目录 / 端口通不通 / 扩展在不在 / node 能否运行 / 数据目录在哪） | 高 —— 以后换电脑你自己就能定位 | 低 |
| 2 | **启动时的提示里直接给出「改成什么」**：现在就提示原因，但没告诉用户「按你这种情况，建议把 .env 改成 XXX」 | 中 | 低 |
| 3 | **让看板/popup 显示当前数据目录** | 中 —— 一眼知道数据在哪，避免「以为丢了」 | 低 |
| 4 | **把诊断信息分细**：现在 `mkdir` 失败和写文件失败报的是同一个路径，容易误判 | 低 | 低 |
| 5 | **自动把整个包复制到用户目录再运行**（彻底自动化） | 中 | **高** —— 会在用户不知情的地方复制一份程序，容易更混乱，我不建议 |

我推荐 **1 + 3**（1 解决「以后怎么自己查」，3 解决「数据在哪」这个反复出现的困惑）。

---

## 六、我不建议做的事

- ❌ **用管理员身份运行**：能绕过一部分 ACL，但治标不治本，而且用户平时不会记得用管理员启动
- ❌ **硬改 D 盘根目录权限**：影响面太大，可能影响同一台机器上别的东西
- ❌ **关闭杀毒软件长期运行**：为了一个工具关掉整机防护，不划算（临时验证一次可以）
- ❌ **把数据目录设在 `C:\Program Files` 下面**：那是受保护目录，一样写不进去
