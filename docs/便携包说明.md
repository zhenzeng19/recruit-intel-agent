# 便携包 —— 装到「只有浏览器」的电脑上

## 什么时候用它

目标电脑**除浏览器外什么都没有**（没有 Node、没有 npm、不能联网装东西、没有管理员权限）时用它。

对比一下三种方式：

| 方式 | 目标机需要 | 数据 | 适合 |
|---|---|---|---|
| `npm run start`（源码/产物） | Node ≥ 20 | 本机 | 你自己的开发机 |
| **便携包** | **只要浏览器** | **各自独立一份** | 拷到另一台电脑单机用 |
| 局域网客户端（见下） | 只要浏览器 | 两台共用一份 | 两台都在用、想看到同一批人 |

## 生成

```bash
npm run build          # 先构建三端产物
npm run portable       # 组装便携包 + 打 zip
npm run portable -- --no-zip    # 只组装，不打 zip
```

产物（都在仓库**同级**，与源码/数据物理隔离）：

```
招聘agent-portable/                 解压即可直接用（89.5 MB）
招聘agent-便携版-v<版本>.zip        拷 U 盘 / 网盘用（约 33 MB）
```

脚本会做**前置检查**（产物是否存在、产物里的扩展版本是否与源码一致）和**编码自检**（见下），任何一项不过就中止。

## 包里有什么

| 文件 | 作用 |
|---|---|
| `node\node.exe` | **捆的 Node 运行时（87 MB）** —— 就是它让目标电脑免安装（官方 win-x64 发行是单文件，不需要额外 DLL） |
| `server\index.js` | 后端服务，自包含单文件（含全部依赖） |
| `web\` | 看板前端静态文件 |
| `extension\` | 浏览器扩展（「加载解压缩的扩展」选它） |
| `data\` | 数据目录，**默认留空** → 首启自动灌 22 份虚构示例数据 |
| `.env` | `DATA_DIR=data`、`SERVER_PORT=8787`（**纯 ASCII**） |
| `启动看板.vbs` | 双击即用：后台静默启动 → **等端口真的监听上再开浏览器** → 起不来会弹框提示 |
| `启动看板-带日志.bat` | 带控制台输出，排查问题用 |
| `停止看板.bat` | 按端口找到进程并结束 |
| `使用说明.txt` | 给使用者看的中文说明（含 FAQ） |

**为什么不需要任何额外配置**：`apps/server/src/env.ts` 的 `findEnvFile()` 会从 `server\` 向上找 `.env`，命中包根那份；`DATA_DIR` 是相对路径、**基准是 `.env` 所在目录**，所以数据自然落在包内 `data\`。这两个既有机制正好让便携包自包含。

## 四条硬约束（务必转达给使用者）

1. **端口必须保持 8787。** 扩展里的后端地址是**构建期写死**的 `http://localhost:8787`；便携包改了端口，扩展立刻连不上（除非回源码改 `.env` 的 `VITE_API_BASE` + `SERVER_PORT` 后重新 build 并重新生成便携包）。
2. **两台电脑的数据各自独立，不会互相同步。** 想共用一份 → 见下面「局域网」。
3. **只支持 Windows x64。** 捆的是 win-x64 版 Node；32 位系统不行（ARM 版 Windows 一般能靠 x64 模拟跑，但未验证）。
4. **可能触发 SmartScreen / 杀软。** 包里的 `node.exe` 是未签名的官方运行时，加上 `.vbs` 启动脚本容易被拦 —— 需要「更多信息 → 仍要运行」或把文件夹加白名单。

## ★ 编码约定（改这个脚本前必读）★

Windows 批处理的编码是个**非常隐蔽的坑**，这里踩过：

> **`.bat` 里的非 ASCII 字节会让 cmd 解析错位。** cmd 是**按字节偏移、用当前控制台代码页**逐行读取批处理文件的；文件编码与控制台代码页不一致时行边界会错乱，表现为**整段命令被跳过、或跳到错误的标签**，而且**完全不报错**。
>
> 实测（同一个启动脚本）：UTF-8 + `chcp 65001` → 打印了横幅**又**错误地跳进 `:missing`（正确路径和错误路径的文本同时出现，自相矛盾）；改成 GBK + 不切代码页 → **更糟**，只输出一个 `pause` 提示，其余什么都没执行。

所以约定是：

| 文件 | 编码 | 原因 |
|---|---|---|
| `.bat` | **纯 ASCII**（一个中文都不放） | 见上。中文说明放到 `.txt` / `.vbs` 里 |
| `.vbs` | **UTF-16LE + BOM** | WSH 对中文支持最稳，且不受控制台代码页影响 |
| `.txt` | **UTF-8 + BOM** | 记事本双击能正确显示中文 |
| `.env` | **纯 ASCII** | 省掉「BOM 会不会破坏第一个键」这类无谓风险 |

纯 ASCII 的 `.bat` 里**再**加 `chcp 65001` 是安全的（所有字节 <128，无可错位之处），正好用来让 Node 输出的 UTF-8 中文日志不花屏。

`make-portable.mjs` 末尾会**自检编码**：非 ASCII 字节数、BOM 是否存在，不合格直接 `exit 1` 并指出是哪个文件。

## 局域网：两台电脑共用一份数据

适用：两台电脑在同一个局域网 / 同一个 WiFi 下，其中一台常开。

1. **主机**（数据要存的那台）正常跑服务 —— 便携包或源码都行。服务端已经监听 `0.0.0.0`，网络侧不用配。
2. 查主机内网 IP：`ipconfig` → 「IPv4 地址」，例如 `192.168.1.6`。
3. **客户端**那台打开 `http://192.168.1.6:8787/` —— 能打开就说明网络通了。
4. 扩展那一端**必须重新构建**：`.env` 的 `VITE_API_BASE` 改成 `http://192.168.1.6:8787`，**并且**把该地址加进 `apps/extension/manifest.json` 的 `host_permissions`（否则浏览器会拦掉上报），然后 `npm run build`，再把扩展装到客户端电脑。

> ⚠️ **扩展只能往 `host_permissions` 里声明过的地址发数据**，这是浏览器的硬规则 —— 光改 `.env` 不够。
> ⚠️ 建议给主机配**固定的内网 IP**，否则路由器重新分配 IP 后扩展就连不上了。
>
> 权衡：好处是数据只有一份、两边看到同一批人；代价是主机必须开着，且扩展要按 IP 重新构建。

## 验证便携包是否可用（改完脚本后跑一遍）

在临时副本上验证，别动你正在用的那份：

```powershell
$src = "<项目所在目录>/招聘agent-portable"
$tst = "$env:TEMP\ria-check"
Copy-Item $src $tst -Recurse -Force
# 换个端口，避免和你正在跑的服务冲突
(Get-Content "$tst\.env" -Raw) -replace 'SERVER_PORT=8787','SERVER_PORT=8898' | Set-Content "$tst\.env"
# 用【包内自带】的 node 启动
Start-Process "$tst\node\node.exe" "`"$tst\server\index.js`"" -WorkingDirectory $tst
# 然后验证：dataDir 落在包内 data\、首启灌了 22 人、看板 200
```

要点：
- 用**包内的 `node\node.exe`** 启动，不要用系统 `node`（否则验不出「捆绑运行时是否可用」）。
- 用**临时副本 + 换端口**，并且**别在测试里运行 `停止看板.bat`** —— 它按端口杀进程，会杀掉你自己正在用的服务。
- `.vbs` 想验证语法又不产生副作用：VBScript **先编译整个脚本再执行**，所以在 `Option Explicit` 后面插一行 `WScript.Quit 0`，用 `cscript //nologo` 跑 —— 退出码 0 且无输出即语法无误，且什么都不会执行。
