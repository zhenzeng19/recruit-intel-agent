## 二、日常怎么做（你只需要记 4 条）

打开项目文件夹，右键 → 「在终端中打开」（或在 VS Code 里按 `` Ctrl+` ``），然后：

```bash
# ① 看现在有没有改动
git status

# ② 看具体改了什么内容（不是文件名，是代码）
git diff

# ③ 提交（把当前状态存成一个存档点）
git add -A
git commit -m "一句话说明这次改了什么"

# ④ 看历史
git log --oneline
```

**`git add -A` 会不会把不该提交的东西也加进去？** 不会 —— `.gitignore` 已经挡住了上面那些。
但如果你**新建了**某种不该入库的文件（比如导出的 Excel、临时日志），先确认 `.gitignore` 里有对应规则。

**提交信息怎么写**：这个项目的习惯是 `类型(范围): 中文说明`。
类型用 `feat`（新功能）/ `fix`（修 bug）/ `chore`（杂务）/ `docs`（文档）/ `test`（测试）。
比如：`fix(ext): 修复打码姓名被识别成界面文案`。

**多久提交一次？** 一个「能说清楚的小改动」就提一次。宁可多提几次 —— 每次提交都是一个能回去的点。

## 三、搞砸了怎么退回（这段最值钱）

### 情况 1：改坏了一个文件，想恢复到上次提交的样子

```bash
git status                      # 先看清哪个文件被改了
git restore 路径/文件名          # 丢弃这个文件的改动（⚠️ 改动就没了）
```

只想丢一个文件、保留其它改动时就用它。**没有把握就先 `git stash`**（见情况 5）。

### 情况 2：刚提交完，发现漏了东西 / 提交信息写错了

```bash
# 撤销最后一次提交，但**保留改动**（改动回到「已暂存」状态）
git reset --soft HEAD~1

# 然后重新提交
git commit -m "这次写对的信息"
```

**`--soft` 是关键**：它只撤销「提交」这个动作，代码一点不动。改完再提一次即可。

### 情况 3：想彻底丢弃最近一次提交（含代码改动）

```bash
git reset --hard HEAD~1         # ⚠️⚠️ 代码改动真的没了
```

**用之前务必想清楚。** 如果只是不满意改动、想重来，用情况 2 的 `--soft`。

### 情况 4：想找回某个历史版本的文件

```bash
git log --oneline                       # 找到那个提交的短哈希，比如 6afa8dc
git show 6afa8dc --stat                 # 先看这个提交动了哪些文件
git restore --source=6afa8dc -- 路径/文件名   # 把这个文件恢复成那时的样子
```

### 情况 5：改到一半，突然要去做别的事

```bash
git stash          # 把当前改动临时收起来（工作区变干净）
# ……去忙别的……
git stash pop      # 把改动拿回来
```

### 情况 6：想做个「安全标记」，之后随时能回来

```bash
git branch 改动前的样子     # 起个名字记住当前这个点
```

以后无论怎么折腾，`git reset --hard 改动前的样子` 都能回到这里。

### 情况 7：整个项目搞乱了，想回到最后一次提交的完整状态

```bash
git status              # 看清有哪些改动
git restore .           # ⚠️ 丢弃所有未提交的改动
git clean -fd           # ⚠️ 再删掉所有未跟踪的新文件（会问你要不要删）
```

**注意**：这只影响源码。你的**真实简历数据在 `招聘agent-data/` 里，github 完全碰不到它**，不会被这些命令删掉。

## 四、重要：目前没有硬盘外的备份

现在 14 个提交全都只在这块硬盘的 `.git` 里。**硬盘坏了 = 历史全没。**
（源码本身还打包在便携包里，但**提交历史**会丢。）

三个做法，按推荐排序：

### 做法 A：传到代码托管（Gitee / GitHub 私有仓库）—— 最推荐

- 好处：历史完整、有异地副本、以后换电脑 `git clone` 就能接着开发
- 代价：要注册账号、**必须建私有仓库**（源码里虽然没有账号密码，但业务逻辑不适合公开）
- 做法：在 Gitee/GitHub 建一个**私有**空仓库，然后：

```bash
git remote add origin <仓库地址>
git push -u origin master
```

### 做法 B：放进同步盘（OneDrive / 坚果云等）

把整个项目文件夹（**含 `.git`**）放进同步盘的目录里。简单、不用注册新账号，但要小心同步冲突。

### 做法 C：定期拷到移动硬盘 / 另一块盘

最土但最可靠。拷的时候**整个 `招聘agent` 文件夹一起拷**（`.git` 在里面，历史才完整）。

> 顺带提醒：**便携包（`招聘agent-便携版-v0.5.3.zip`）不等于备份**。
> 它只是「程序 + 空数据」，不含你的提交历史，也不含 `招聘agent-data/` 里的真实简历。
> 真实数据要单独备份 `招聘agent-data/` 文件夹。
